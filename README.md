# ระบบแบบเยี่ยมชั้นเรียน (Classroom Visit System)

เว็บแอปพลิเคชัน Full-stack ภาษาไทย สำหรับบันทึก ประมวลผล และสรุปผลการเยี่ยมชั้นเรียนภายในสถานศึกษา
บันทึกข้อมูลลงฐานข้อมูลจริง (PostgreSQL) พร้อมระบบ CRUD, การอัปโหลดรูปภาพ, การคำนวณคะแนน และการตรวจสอบสิทธิ์ผู้ดูแล

---

## โครงสร้างฐานข้อมูล

| ตาราง | หน้าที่ |
| --- | --- |
| `system_settings` | ชื่อโรงเรียน, ต้นสังกัด, โลโก้, `admin_pin_hash` + salt, ตัวเลือกบังคับแนบรูป |
| `rate_limits` | สถิติการเรียก API สำหรับจำกัดอัตราและกัน PIN brute-force |
| `semesters`, `academic_years` | ภาคเรียน / ปีการศึกษา |
| `classroom_teachers`, `visitors` | ผู้รับผิดชอบชั้นเรียน / ผู้เยี่ยมชั้นเรียน (ชื่อ + ตำแหน่ง) |
| `classrooms` | ชั้นเรียน พร้อมลำดับการแสดงผล |
| `indicators` | รายการตัวชี้วัด พร้อมลำดับ |
| `evaluations` | หัวรายการประเมิน + คะแนนรวม ร้อยละ ระดับคุณภาพ ข้อคิดเห็น |
| `learning_areas` | กลุ่มสาระการเรียนรู้ (ใช้กับการเยี่ยมระดับขั้นพื้นฐาน) |
| `indicator_groups` | หัวข้อกลุ่มของตัวชี้วัด เช่น "แผนการจัดการเรียนรู้" ที่มีข้อย่อย 1.1–1.6 |
| `evaluation_scores` | คะแนนรายตัวชี้วัด + **การดำเนินการ** พร้อม snapshot ชื่อตัวชี้วัดและหัวข้อกลุ่ม |
| `evaluation_images` | รูปภาพประกอบการประเมิน |

ทุกตารางข้อมูลพื้นฐานมีคอลัมน์ `deleted_at` สำหรับ **soft delete**:
ถ้าข้อมูลเคยถูกใช้ในการประเมินแล้ว ระบบจะซ่อนออกจากรายการแทนการลบจริง เพื่อไม่ให้รายงานเดิมเสียหาย

`evaluation_scores.indicator_snapshot` ทำให้รายงานเก่ายังแสดงข้อความตัวชี้วัด ณ วันที่ประเมิน
แม้ผู้ดูแลจะแก้ไขหรือลบตัวชี้วัดนั้นในภายหลัง

## โครงสร้างแบบประเมิน

แต่ละตัวชี้วัดบันทึก 2 ค่าคู่กัน และบังคับกรอกทั้งคู่:

| ส่วน | ค่าที่บันทึก | มีผลต่อคะแนน |
| --- | --- | --- |
| **การดำเนินการ** | ปฏิบัติแล้ว / กำลังปฏิบัติ / ยังไม่ปฏิบัติ | ไม่มี (เป็นข้อมูลเชิงคุณภาพ) |
| **ผลการดำเนินการ** | คะแนน 1–5 | ใช้คำนวณคะแนนรวมและระดับคุณภาพ |

ตัวชี้วัดจัดเป็น **หัวข้อกลุ่ม** ได้ ระบบจะเรียงตามลำดับกลุ่มแล้วจึงเรียงภายในกลุ่ม
และแสดงเลขข้อเป็น `1.1`, `1.2`, `2.1` โดยอัตโนมัติทั้งในฟอร์ม หน้ารายละเอียด และเอกสารพิมพ์
ตัวชี้วัดที่ไม่ได้อยู่ในกลุ่มใดจะแสดงเป็นรายการเดี่ยวต่อท้าย

### ระดับการศึกษาและข้อมูลวิชา

ตอนที่ 1 ต้องเลือก **ระดับการศึกษา** (ปฐมวัย / ขั้นพื้นฐาน) — ระบบเดาให้อัตโนมัติจากชื่อชั้นเรียนที่เลือก แต่แก้ไขได้

- **ปฐมวัย** → ไม่ต้องระบุข้อมูลวิชา
- **ขั้นพื้นฐาน** → ต้องระบุ **วิชา**, **รหัสวิชา** และ **กลุ่มสาระการเรียนรู้** (บังคับทั้งฝั่ง client และ server)

## การคำนวณคะแนน

```
คะแนนรวม   = ผลรวมคะแนนของตัวชี้วัดทุกข้อ (ข้อละ 1–5)
คะแนนเต็ม  = จำนวนตัวชี้วัด × 5
ร้อยละ     = (คะแนนรวม ÷ คะแนนเต็ม) × 100     (ทศนิยม 2 ตำแหน่ง)
```

| ร้อยละ | ระดับคุณภาพ |
| --- | --- |
| 90.00 ขึ้นไป | ดีมาก |
| 80.00 – 89.99 | ดี |
| 70.00 – 79.99 | ปานกลาง |
| 60.00 – 69.99 | พอใช้ |
| ต่ำกว่า 60.00 | ปรับปรุงแก้ไข |

หน้าเว็บคำนวณแบบ Real-time เพื่อแสดงผลทันที แต่ **ค่าที่บันทึกลงฐานข้อมูลคำนวณใหม่ที่ฝั่ง server เสมอ**
(`src/lib/scoring.js`) ระบบจึงไม่เชื่อคะแนนรวม ร้อยละ หรือระดับคุณภาพที่ส่งมาจาก client

ในหน้าสรุปผล ถ้าผู้รับการเยี่ยมคนเดียวกัน (ในชั้นเรียน ภาคเรียน และปีการศึกษาเดียวกัน)
ถูกประเมินโดยผู้เยี่ยมหลายคน ระบบจะเฉลี่ยคะแนนจากผู้เยี่ยมทุกคน ทั้งระดับภาพรวมและรายตัวชี้วัด

## การดูเอกสาร / พิมพ์ / บันทึกเป็น PDF

กดปุ่ม **“ดูเอกสาร / พิมพ์ PDF”** ระบบจะสร้างเอกสารรูปแบบราชการขึ้นใหม่ (ไม่ใช่การพิมพ์หน้าจอ)
แล้วเปิด **ตัวแสดงเอกสารบนหน้าจอ** ให้ตรวจสอบก่อน โดยแสดงเป็นหน้ากระดาษ A4 เหมือนตอนพิมพ์จริง

ความสามารถของตัวแสดงเอกสาร:

| ส่วน | การใช้งาน |
| --- | --- |
| ตัวเลขหน้า | บอกจำนวนหน้าทั้งหมดของเอกสาร |
| ปุ่ม − / + | ย่อ–ขยาย 30%–200% |
| ปุ่ม “พอดีความกว้าง” | ย่อให้พอดีหน้าจอ (บนมือถือระบบตั้งให้อัตโนมัติ) |
| ปุ่ม “พิมพ์ / บันทึก PDF” | เปิดหน้าต่างพิมพ์ของเบราว์เซอร์ — เลือกปลายทาง **“บันทึกเป็น PDF / Save as PDF”** เพื่อได้ไฟล์ PDF |
| ปุ่ม ✕ หรือปุ่ม Esc | ปิดตัวแสดงเอกสาร |

ระบบใช้กลไกพิมพ์ของเบราว์เซอร์ในการสร้าง PDF จึงได้ตัวอักษรภาษาไทยที่ถูกต้องสมบูรณ์
(สระ วรรณยุกต์ และการตัดคำ) โดยไม่ต้องฝังฟอนต์เพิ่มหรือติดตั้งโปรแกรมใด ๆ

| หน้า | เอกสารที่ได้ |
| --- | --- |
| รายละเอียดผลการเยี่ยมชั้นเรียน | **แบบบันทึกการตรวจเยี่ยมชั้นเรียน** — หัวเอกสาร (โลโก้/ชื่อโรงเรียน/ต้นสังกัด), ข้อมูลผู้รับการเยี่ยมและผู้เยี่ยม, ตารางตัวชี้วัดพร้อมเครื่องหมาย ✓ ในช่องคะแนน 5–1, แถวสรุปคะแนน, ข้อคิดเห็น, ช่องลงชื่อ 2 ฝ่าย และหน้าภาพประกอบ |
| รายละเอียดสรุปผลการเยี่ยมชั้นเรียน | **แบบบันทึกสรุปการตรวจเยี่ยมชั้นเรียน** — ตารางแยกตามครั้งที่/วันที่/ผู้เยี่ยม/คะแนน/ระดับคุณภาพ + หน้าสรุปคะแนนรายตัวชี้วัดของผู้เยี่ยมแต่ละคน + ข้อคิดเห็นทุกครั้ง + หน้าภาพประกอบ |
| สรุปผลการเยี่ยมชั้นเรียน (เมนูผู้ดูแล) | **แบบบันทึกสรุปผลการเยี่ยมชั้นเรียน** — รายชื่อผู้รับการเยี่ยมทั้งหมดในภาคเรียน/ปีการศึกษาที่เลือก |

กำหนดเป็นกระดาษ A4 แนวตั้ง ขอบ 14×15 มม. ตารางมีเส้นขอบทึบ ไม่ตัดคำกลางแถว
และหัวตารางแสดงซ้ำเมื่อขึ้นหน้าใหม่ ชื่อไฟล์ PDF เริ่มต้นจะตั้งตามชื่อเอกสารและผู้รับการเยี่ยมโดยอัตโนมัติ

## ความปลอดภัย

- PIN ผู้ดูแลเก็บเป็น **scrypt hash + salt** ไม่เคยส่ง PIN หรือ hash กลับไปยัง frontend
- Session เป็นคุกกี้ `HttpOnly` + `SameSite=Strict` ลงลายเซ็น HMAC อายุ 2 ชั่วโมง
  (ตั้ง `SECURE_COOKIE=1` เมื่อ deploy ผ่าน HTTPS)
- ตรวจสอบสิทธิ์ทั้งระดับ API (`/api/admin/*`) และระดับหน้าเว็บ (`/admin*`) — เซสชันหมดอายุจะกลับไปหน้ากรอก PIN
- คำขอที่เปลี่ยนแปลงข้อมูลต้องมี header `X-Requested-With` (ป้องกัน CSRF ร่วมกับ SameSite=Strict)
- กรอก PIN ผิดครบ 5 ครั้ง จะถูกระงับชั่วคราวและเพิ่มเวลาแบบทวีคูณ (สูงสุด 15 นาที)
- ใช้ prepared statement ทุกคำสั่ง SQL และแสดงข้อความทั้งหมดด้วย `textContent` (ป้องกัน SQL Injection และ XSS)
- ตรวจสอบชนิดและขนาดไฟล์รูปภาพ (JPG/JPEG/PNG/WEBP, ไม่เกิน 5 MB, สูงสุด 10 ไฟล์) และตั้งชื่อไฟล์ใหม่แบบสุ่มเสมอ
- ตั้งค่า Content-Security-Policy, `X-Content-Type-Options`, `X-Frame-Options` และ `Referrer-Policy`
- การลบผลการประเมินจะลบคะแนนรายตัวชี้วัดและไฟล์รูปภาพที่เกี่ยวข้องทั้งหมด

## ตัวแปรสภาพแวดล้อม

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `PORT` | `3000` | พอร์ตของเซิร์ฟเวอร์ |
| `DB_FILE` | `data/app.db` | ตำแหน่งไฟล์ฐานข้อมูล |
| `SESSION_SECRET` | สร้างอัตโนมัติที่ `data/.session-secret` | กุญแจลงลายเซ็น session |
| `SECURE_COOKIE` | (ไม่ตั้ง) | ตั้งค่าเมื่อใช้งานผ่าน HTTPS |
| `SEED_PIN` | `2468` | PIN เริ่มต้นตอนสร้างข้อมูลตั้งต้น |

## หมายเหตุการดูแลระบบ

- แก้ไข class ของ Tailwind ใน HTML/JS แล้วต้องรัน `npm run build:css` ใหม่เสมอ
- ไฟล์ CSS/JS อ้างอิงด้วย `?v=__ASSET_V__` ซึ่งเซิร์ฟเวอร์แทนที่ด้วยเวอร์ชันที่คำนวณจากเวลาแก้ไขไฟล์จริง
  ผู้ใช้จึงได้ไฟล์ใหม่ทันทีหลังอัปเดตระบบ โดยไม่ต้องล้าง cache เอง
- ไฟล์ `.html` เข้าถึงโดยตรงไม่ได้ ต้องผ่าน route ของระบบเสมอ (`/`, `/admin`, `/admin/evaluation`, `/admin/summary-detail`)
- สำรองข้อมูลโดยคัดลอกโฟลเดอร์ `data/` และ `uploads/` ไปพร้อมกัน
- ตัวชี้วัดที่ปิดใช้งานจะไม่ปรากฏในแบบประเมินรายการใหม่ แต่ผลการประเมินเดิมยังคงแสดงครบถ้วน
